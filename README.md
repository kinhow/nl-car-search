# NL Car Search

Natural-language search for a used-car marketplace. Type what you want the way you'd say it, in English, Malay or Manglish, and an LLM turns it into filters you can edit, ranks results by what you meant, and answers questions about a car using only its listing and a buyer's guide.

**Live demo:** _link coming_ · **Stack:** Next.js 16, TypeScript, Claude Haiku 5.5 (Anthropic SDK, structured outputs), Voyage embeddings, Vitest, GitHub Actions

> All 2,000 listings are synthetic, generated by [`scripts/generate-listings.ts`](scripts/generate-listings.ts). Makes and models are real Malaysian-market cars; prices, sellers and descriptions are made up.

## What it does

```
"auto Honda under 80k, after 2018, near PJ, good for Grab"
        │
        ▼
1. Query → filters      Claude Haiku 5.5 with a Zod schema (structured output). Enums come from the
                        catalog, so it can't invent a model. Soft preferences go to `semantic_query`.
        │               { make: Honda, transmission: auto, price_max: 80000, year_min: 2018,
        │                 states: [Selangor], semantic_query: "good for e-hailing" }
        ▼
2. Guardrails           Drop impossible make/model pairs, swap reversed ranges, read "80" as RM80k,
        │               ignore out-of-range years. Vague query → ask one clarifying question.
        │               LLM down or unusable → keyword fallback, and the UI says so.
        ▼
3. Hybrid retrieval     Hard filters narrow the set; Voyage embeddings rank what's left by the soft
        │               preference (cosine similarity, 2,000 × 512-dim vectors in memory).
        ▼
4. Grounded answers     "How much is the road tax?" → retrieve 3 guide sections, answer only from
                        them and the listing, cite sources, decline when the answer isn't there.
```

Filters show as chips. Removing one re-runs the search without calling the LLM again.

## Evals

Every change to a prompt, schema or model is measured, not eyeballed. `npm run eval` runs three suites against the real models; CI runs them on every push and posts the table to the job summary.

| Suite | What it checks | How it's graded |
|---|---|---|
| **Query → filters** ([91 cases](evals/parse-cases.json)) | English, Malay, Manglish, vague queries, units traps ("50k km" isn't a price), cars the marketplace doesn't stock, prompt injection | Every one of 12 filters compared with a hand-written label. Filters the user didn't ask for count as errors. |
| **Retrieval** ([24 cases](evals/retrieval-cases.json)) | Does "good for Grab driving" find e-hailing cars when no description says "Grab"? | Each listing has hidden ground-truth traits that are never embedded. Precision@10 against the random baseline. |
| **Grounded answers** ([24 cases](evals/ask-cases.json)) | Road-tax calculations, guide facts, listing facts, unanswerable questions, injection | Deterministic checks: required values in the answer, required citations, `grounded` false when it should decline. |

## Run it

```bash
npm install
cp .env.example .env.local      # add ANTHROPIC_API_KEY and VOYAGE_API_KEY
npm run data:embed              # one-off: embeds listings and guide (~US$0.01)
npm run dev                     # http://localhost:3000

npm test                        # unit tests, no keys needed
npm run eval                    # all eval suites (needs keys)
```

`npm run data:generate` rebuilds the synthetic listings (seeded, so the output is the same each time). Rerun `data:embed` afterwards.

## Design choices

- **Structured output, not free text.** `client.messages.parse` with a Zod schema guarantees valid JSON and valid enum values, so the guardrails only check that the values make sense together.
- **Nullable by default.** Every filter can be `null`, and the prompt says to leave unmentioned fields empty. The eval counts made-up filters separately, because over-filtering silently hides good cars.
- **Haiku 5.5 at low effort.** Extraction is a narrow task. The eval shows whether a bigger model would be worth paying for.
- **No vector database.** 2,000 vectors fit in 4 MB of memory. A database would add setup without improving the demo.
- **Hidden traits for honest retrieval evals.** Descriptions imply traits ("fits a stroller and golf bag") without naming them, so retrieval has to work on meaning.
- **Fails visibly.** If the LLM or embeddings fail, search falls back to keyword matching or year order, and the UI shows a note instead of an error.

## Project layout

```
src/lib/parse-query.ts   query → filters (Claude, structured output)
src/lib/validate.ts      guardrails between the LLM and the index
src/lib/search.ts        filtering, sorting, keyword fallback
src/lib/vector-index.ts  in-memory vectors, semantic ranking, guide retrieval
src/lib/ask.ts           grounded answers with citations
src/lib/run-search.ts    the full pipeline, shared by the API route and the evals
src/data/                catalog, synthetic listings, buyer's guide, vectors
evals/                   labelled cases, runner, latest results
```
